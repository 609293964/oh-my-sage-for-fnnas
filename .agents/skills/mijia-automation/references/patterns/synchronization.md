# 同步与防回环模式

本文件是跨案例设计指导，不表示其中每个完整拓扑均已实机验证。具体运行结论以案例和实验的证据状态为准。

## 单向属性镜像

```text
源属性更新 → 可选转换 → 目标属性写入
```

只有在类型、单位、量程和步进一致时才可直接镜像；否则先转换和夹紧。

## 双向同步

最小差值门控：

```text
A 或 B 更新 → 标准化 A/B → 比较差值
不同 → 由触发侧写目标侧
相同 → 停止
```

差值为 0 只能说明稳态相等，不能证明不存在回环。可靠设计还要考虑：

- 来源标记或执行锁。
- 去抖与节流。
- 浮点容差或离散档位。
- 设备夹紧、量化和拒绝值。
- 双方同时操作的优先级。
- 离线恢复和启动时初值竞争。
- 最大操作次数或收敛监控。

## 开关状态

仅当双方严格归一为 0/1 时可用简单差值。未知值和第三状态必须单独处理。

### 布尔开关对的四分支写法（已实机验证）

两台设备要「同开同关」时，最容易写成两条无条件镜像：

```text
A 变 true → 写 B = true
B 变 true → 写 A = true
```

只要状态上报延迟或乱序，双方就会互相喂招，负载快速反复通断。

改为每个方向都先查目标状态，不一致才写：

```text
A 变 true → deviceGet B == true ?
              output  (已一致) → []          ← 回声在此终止
              output2 (不一致) → 写 B = true
```

四个方向（A 开 / A 关 / B 开 / B 关）各一条，共 12 个节点。

**收敛性**：每次写入都指向「两边相等」这一个终点，不存在越写越反的路径。回声绕回来时双方已一致，链条自行断开。即使查询命中陈旧缓存导致多绕一两轮，仍必然收敛——这是它与无条件镜像的根本区别。

**配套要点**：

- 四个触发器的 `preload` 必须为 `false`。设为 `true` 时规则启用瞬间四个触发器同时评估，若当时两边不一致会互相打架（一个要开 B，另一个要关 A）。
- 该结构对控制来源不敏感：实体按键、App、语音助手改状态都会被同步。
- 与「一键全关」这类批量规则天然兼容：批量操作同时改变两侧，同步规则查得一致后不再追加写入。

## 单主多从和状态驱动切换

多设备保持一致时，优先选一个事实源，其他设备只单向跟随，避免全互联回环。短延时只能吸收部分通知时序，不能替代重试、最终校验和快速连续操作测试。

设备存在多个外部控制入口时，内部模式位置不能当作设备真实状态。按最近已知设备状态查询下一档，并为未知、离线、未覆盖区间设计兜底。连续值先分成无重叠、无空洞的离散区间。

## 数值参数

比较前先转换到同一规范量程。双向有损映射可能永远不完全相等，应使用容差或离散档位，不能严格 `!= 0`。

## 颜色值

不同设备可能使用十六进制文本、十进制整数或厂商编码。没有经过双方能力验证和可逆转换时，只做单向同步。
