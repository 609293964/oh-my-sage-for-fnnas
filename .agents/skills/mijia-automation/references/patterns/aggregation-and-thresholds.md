# 聚合与阈值模式

本文件是跨案例设计指导，不表示其中每个完整拓扑均已实机验证。具体运行结论以案例和实验的证据状态为准。

## 多源最值与平均值

```text
多个设备值 → 各自变量 → 任一更新汇合 → min/max/平均值 → 判断
```

- `min`：任一区域偏低时触发。
- `max`：任一区域偏高时触发。
- 平均值：形成群体基准。

风险：不同刷新时间、离线旧值、部分初始化和单位不一致。生产规则应增加就绪状态或 preload 屏障。

## 群体偏差

```text
平均值 = sum(values) / n
偏差_i = abs(value_i - 平均值)
```

下游必须判断 `偏差_i`，不能误用原始值。阈值的 `>` 与 `>=` 是不同需求，必须明确边界。

## 至少满足 k 个

先把每个输入归一化为严格的 0/1：

- 目标状态映射为 1：`sum >= k`。
- 目标状态映射为 0：`sum <= n-k`。

未知、离线或第三枚举不能直接参与计数。先单独归一化或进入异常分支。

## 事件汇合与状态逻辑

- `signalOr` 汇合事件，决定何时重算。
- `logicOr/logicAnd/logicNot` 组合状态，最终连接 `condition.condition`。
- 聚合结果变化只更新状态时，不会自动触发业务动作；需要明确的 trigger。

## 触发、状态和否则

`condition.trigger` 表示何时求值，`condition.condition` 表示当时是否满足。当前网关已实测：事件先到、状态约 500 ms 后才变真时不会回补前一次事件；需要后来成立也执行时，状态变化本身必须成为触发。不同固件和状态源仍保留边界。

“否则”只表示同一次触发到达时状态不满足，不是触发条件的反事件，也不是设备执行失败分支。需要“有人开灯、无人关灯”时，应分别设计有人和无人触发。

空输入和枚举多选的运行语义目前只作为实验边界：不要根据编辑器颜色或视频演示，把空口、集合内切换和未知值写成校验器硬规则。

## 求和兜底分支

一组互斥的 0/1 寄存器可以用求和判断“是否全部未置位”：

```text
汇总 = sum(register_1 .. register_n)
汇总 == 0 → 默认分支（无上下文）
汇总 != 0 → 由各寄存器分别决定具体分支
```

用途是给统一入口一个兜底出口：入口被触发但没有任何上下文时，执行反问或提示，而不是静默无响应。

- 参与求和的必须是严格 0/1，且归零路径可靠，否则残留值会永久屏蔽默认分支。
- 求和只回答“有没有上下文”，不回答“是哪一个”，分发仍需逐个判断寄存器。
- 汇总节点与各分支由同一事件触发时，其求值顺序需实测；结构上不保证汇总先于分支完成。

## 反例

- 三路传感器只有一路初始化就开始求平均。
- 计算差值后，下游仍比较原始温度。
- 把“任一区域偏暗”错误实现成平均照度偏暗。
- 只判断二值求和等于 1，漏掉多个传感器同时为 1。
