# 时间与时长模式

本文件是跨案例设计指导，不表示其中每个完整拓扑均已实机验证。具体运行结论以案例和实验的证据状态为准。

## 单次时长

```text
开始事件 → start = now()
结束/查询事件 → end = now()
durationMs = end - start
```

随后按需要换算分钟、小时和天。边界分段应先定义区间是否包含端点；不要先 `round()` 再用 60/1440 分段，除非提前跨档正是需求。

必须处理：重复开始、缺失开始、重复结束、重启、时钟回拨和负时长。

## 累计时长

```text
本次时长 = (结束 - 开始) / 单位
累计时长 = 累计时长 + 本次时长
```

需要去抖和状态机，避免功率在阈值附近反复结算。周期清零要定义跨午夜运行如何归属。

## 长周期提醒

时间戳差适合替代长时间 loop，但必须明确“起点代表什么”：初始化、上次提醒、上次确认还是实际维护事件。

提醒后自动重置起点会把“提醒周期”误写成“实际维护周期”。如果业务关心真实充电/保养，应增加用户确认或真实设备事件。

## 日期快照

```text
周期触发 → month()/date()/day() → 状态变量
业务事件 → 读取日期状态 → 分支
```

风险：零点任务漏执行、规则在月中启用、时区、跨月顺序和离线恢复。可即时计算时，不必长期缓存日期变量。

跨年月份范围使用“年末区间 OR 年初区间”；边界落在月中时必须同时考虑日期，不能只看月份。

## 节律和动态时间窗口

固定时间段和日出驱动的动态时间段都应先定义每段起点、终点和跨日恢复。日出自适应只说明时间起点变化，不等于读取环境光的闭环自适应。

- 规则中途启用时，优先按当前时间计算理论位置，不从陈旧变量继续累加。
- 每段结束夹紧目标值，并处理错过开始/结束事件。
- 验证时区、经纬度来源、跨午夜、夏令时和 `remaining > 0`。
- 家庭位置和作息只留在私有配置，不进入公开模板。

推荐执行顺序：

1. 计算当前所属时间段。
2. 根据当前时间直接计算理论值，不从陈旧累计值继续加：`progress = clamp((now-start)/(end-start), 0, 1)`，`value = startValue + progress*(targetValue-startValue)`。
3. 按目标设备 step 量化。
4. 使用 `min/max` 同时夹紧分段目标和 MIOT 范围。
5. 写入设备；到终点停止 loop。
6. 中途启用、错过边界或跨日时重新计算当前位置。

当前网关已验证 `month()`、`hours()` 可在运行时取值，且 `min()` 能将超调表达式夹紧到目标值；时区、跨月和完整全天曲线仍需验证。
